# Project Specification: Autonomous PR Code Reviewer (Agentic CI/CD)

## 1. Product Requirements Document (PRD)

### 1.1 Overview
We are building a secure, automated pull request (PR) reviewer using GitHub Actions, TypeScript, and the Anthropic API. When a developer opens or updates a PR, this system fetches the code diff, sanitizes it to prevent token leakage, passes it to an LLM with strict review guidelines, and automatically posts constructive, inline Markdown comments back onto the PR.

### 1.2 Core Goals
*   **Automate the mundane:** Catch syntax issues, structural anti-patterns, and obvious logical flaws before a human reviewer looks at the code.
*   **Security first:** Ensure hardcoded secrets or API keys in the diff are redacted before being sent to the LLM provider.
*   **Fail-closed reliability:** The LLM output must be strictly validated against a JSON schema. If the LLM hallucinates or returns malformed data, the pipeline must fail gracefully without posting garbage to the PR.

### 1.3 Core Concepts & Glossary
*   **PR Diff:** The raw text representation of code changes provided by GitHub's API.
*   **Sanitization Pipeline:** A utility that uses regex to strip common secret patterns (e.g., `sk-...`, `Bearer ...`) and truncates massive diffs to stay within token limits.
*   **Structured JSON Output:** The exact format the LLM is forced to return, ensuring we can parse it programmatically.
*   **Fail-Closed:** A design principle where unexpected behavior (like a failed Zod parse) halts the execution rather than proceeding with assumptions.

### 1.4 User Flow
1.  Developer pushes code and opens a Pull Request on GitHub.
2.  The `.github/workflows/ai-reviewer.yml` Action is triggered.
3.  The Action provisions a Node environment and runs our compiled TypeScript app.
4.  The app uses `Octokit` to fetch the raw `.diff` of the PR.
5.  The app sanitizes the diff (redacts secrets, checks length).
6.  The app sends the diff and a highly specific System Prompt to the Anthropic API, requesting JSON output.
7.  The response is parsed and validated using `zod`.
8.  The app iterates through the validated JSON and uses `Octokit` to post inline PR review comments on the specific files and line numbers.

### 1.5 Acceptance Criteria
*   [ ] The GitHub Action runs successfully on `pull_request` (`opened`, `synchronize`) events.
*   [ ] The system successfully authenticates with both GitHub (via `GITHUB_TOKEN`) and Anthropic (via `ANTHROPIC_API_KEY`).
*   [ ] Mock secrets placed in a test PR are successfully redacted before the LLM payload is built.
*   [ ] The system successfully posts at least one inline comment on a test PR.
*   [ ] If the LLM returns invalid JSON, the Action logs a descriptive error and exits with code 1, posting nothing to the PR.

## 2. Technical Requirements Document (TRD)

### 2.1 Tech Stack & Dependencies
*   **Runtime:** Node.js (v20+)
*   **Language:** TypeScript
*   **GitHub SDK:** `@actions/core` (for workflow logging/inputs), `@actions/github` (Octokit for API calls)
*   **LLM SDK:** `@anthropic-ai/sdk`
*   **Validation:** `zod`
*   **Tooling:** `tsx` for running TypeScript directly, `esbuild` or `tsc` for compilation.
